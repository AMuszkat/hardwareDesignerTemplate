# Board Setup from `14_fab.md`

The rule page is `<board>/handoff/14_fab.md`, generated by concept. The tool
that types it into KiCad is `tools/board_setup/board_setup.py`
(`tools/board_setup/README.md` is the whole story). Do not set these numbers
by hand in Board Setup, and do not set them through Konnect's
`set_design_rules` / `create_netclass`: those write a subset and nothing
checks them afterwards.

Always through `tools/kpy`. It is the only way to reach the interpreter that
imports `pcbnew`.

## 1. Plan (read-only, board may be open)

```
tools/kpy tools/board_setup/board_setup.py plan --board <board>
```

Read the whole output before going on:

- **UNSET values listed.** The concept session has not decided them. `apply`
  will refuse; that is a **QUESTIONS.md** item quoting the MANIFEST hashes.
  Never fill one locally.
- **It stopped with a parse error.** The page changed shape, or gained a rule
  the script does not know. Teach `parse_fab` the new row, keeping the
  strictness. Never make it skip a row.
- **"net 'X' is not on the board yet"** (tagged `board`). Expected before the
  schematic is drawn and the netlist pushed: everything else is applied, and
  you re-run `apply` once the net exists. If the schematic is complete and the
  net still is not there, the page names a net that does not exist: a
  **QUESTIONS.md** item.
- **"net 'X' matches 2 board nets"** (tagged `QUESTION`). The page is
  ambiguous; `apply` stops. Do not guess which net was meant.
- **UNVERIFIED notes.** Applied as written; they matter at order time, not now.
- **The derived rules** (silk clearance, area classes, no-via classes) are
  printed with their reasoning. If the page's wording changed so a derivation
  no longer holds, fix the script, not the output.

## 2. Apply (KiCad must be closed)

`apply` refuses while a KiCad lock file exists. The **whole project** must be
closed, not just the PCB editor: KiCad rewrites `.kicad_pro` when the project
closes, and that would undo the net classes. Ask the user to save and close
it, unless they have said you may close KiCad yourself. Then:

1. Save everything open in KiCad (Konnect `save_project` for the board).
2. Quit. There is no quit command over the IPC API; `kill -TERM` on the
   `kicad` process is the way. KiCad does not rewrite project files on SIGTERM.
3. Confirm `pgrep -x kicad` is empty. Only then remove the stale `~*.lck`
   files it leaves behind; they belong to a process that no longer exists.

Never pass `--ignore-lock` while any KiCad process runs.

```
tools/kpy tools/board_setup/board_setup.py apply --board <board>
```

It backs up to `<board>/.board_setup_backups/<timestamp>/` and writes the
rules through `pcbnew.SaveBoard`, the generated block in `<board>.kicad_dru`,
and the **physical stackup** (through a scratch copy KiCad parses, proved by
diff to move nothing else). Then `check` runs in a fresh process. Re-running
is safe: with nothing to change it says so and only checks.

## 3. Check, then DRC

```
tools/kpy tools/board_setup/board_setup.py check --board <board>
```

It exits 0 only when everything matches, stackup included. Each difference is
tagged: `apply` (re-run apply), `QUESTION` (the page is wrong or incomplete —
QUESTIONS.md), `board` (your own work: the outline, placing the footprint an
area class names). Then run DRC the way the placement skill does (parity on)
and read what the new rules produce. The usual first findings, all resolved
without touching a rule:

- **`text_thickness`**: stock reference fields are thinner than the page's
  silk stroke. Set designators to the Board Setup minimum (the placement
  skill's labels step).
- **`solder_mask_bridge`** inside fine-pitch parts: with the fab's minimum web
  KiCad merges their openings, which is the ganging the page asks for. Set
  KiCad's per-footprint "allow solder mask bridges" flag (`fp.py tidy <name>
  --allow-mask-bridges`). Never lower the web.
- **`clearance`** inside a vendor land below the fab's floor: a land that
  cannot meet the fab's own floor is a QUESTIONS.md item, not a local rule.

## When to run it again

- **The CHANGELOG lists `14_fab.md`** among the pages that changed, or the
  sha256 printed by `check` differs from the one in the `.kicad_dru` header:
  `plan`, then `apply`.
- **Nets renamed in the schematic.** Net-class assignments are exact names
  (the tool escapes them, so `D[0]` does not also take `D0`), so a rename
  silently drops a net to Default. `check` catches that (the
  `net -> class` line). Re-apply.
- **Before placement, before routing and before fab output.** `check` must
  exit 0.

## Rules

1. **Do not loosen a number to make routing or DRC fit, and do not tighten
   one on the assumption the fab can do better.** A rule that blocks the
   layout is a QUESTIONS.md item.
2. **The script writes; you do not.** No manual Board Setup edits to these
   fields. Nothing inside the generated `.kicad_dru` block gets hand-edited,
   and no text tool touches `.kicad_pcb` or `.kicad_pro`.
3. **An autorouter gets the edge clearance separately**: Freerouting's
   `router.copperToEdgeClearanceUm` = copper-to-edge × 1000.
