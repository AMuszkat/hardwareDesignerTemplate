# Reading the design diagrams

**Scope:** navigation and visual conventions for the generated sheets in
`design/diagrams/`.
**Not here:** design authority or component status — those remain in
`IMPLEMENTATION.md`, `SPECS.md`, `STATUS.md` and the board handoffs.

## Start broad, then zoom in

| order | sheet | question it answers | how to read it |
|---|---|---|---|
| 1 | [System](diagrams/system.svg) | *(example)* How does the signal get from input to output? | Left to right; teal is feedback; dashed boxes are provisional. |

Every sheet is generated by `tools/diagrams/<name>.py`. Edit the generator,
never the SVG. Open SVGs in a browser and zoom; a fit-to-page thumbnail is not
the intended text size.

## Visual vocabulary

- **Colour is the domain:** blue = digital, green = analog, amber = power,
  teal = feedback/sense, red = protection or a critical constraint.
- **Solid outer frames** group functions. **Dashed part boxes** mark a
  provisional implementation: a named candidate is not a committed part.
- **Arrowheads** show direction; **dots** mark connected branches.
- An amber footer strip in a box names the supply it runs from.
- **System sheets carry function names, never refdes** (lint check 2).
  Board-level sheets may carry refdes.
