# studies/ — the evidence behind every number

Every number the concept session publishes has to come from somewhere a
reader can re-check. There are three acceptable sources: **a datasheet page,
a standard, or a study.** A study is a runnable Python file that answers
**one design question with a number**. The number then goes into
`design/SPECS.md` with the study named as its source, and `--check` guards it
from then on.

Memory, a search snippet, or "it's usually about…" are not sources.

## When to write a study

| you need to… | study type | example |
|---|---|---|
| **size or select** a value (a resistor, a capacitor, a part from candidates) | derivation | `s01_rc_corner.py` |
| **show the design survives** tolerances, temperature, supply range, ageing | robustness: worst case + Monte Carlo | `s02_divider_tolerance.py` |
| **check a budget against a hard line** (thermal, power, noise, timing, error, cost) | budget at the corner | `s03_ldo_thermal.py` |
| **compare options** (topologies, parts, packages, architectures) | trade study: one table, one verdict | the package table in `s03` |
| **model behaviour** (a filter response, a control loop, a transient, a link budget) | simulation | — write your own |

Do **not** write a study when the datasheet states the number: cite the page
instead. Do write one, even if it is ten lines, whenever SPECS will quote a
number nobody can look up. A ten-line study is cheaper than a wrong spec.

## The life of a study

```
 a design question
   │   first: has HISTORY already answered it?  (history/HISTORY.md)
   ▼
 inputs → studies/designpoint.py      each with its source (SPECS row, datasheet page)
   ▼
 studies/sNN_<name>.py                copy _template.py; Question / Decides / Inputs / Headline
   ▼
 run it, read it                      .venv/bin/python studies/run_all.py --only sNN_<name>
   ▼
 the result moves into its homes — by the concept session, never by the study itself:
   ├─ design/SPECS.md        the ACHIEVED number, source = the study, H if a hard line
   ├─ headline() + baseline  run_all.py --check --bless, after looking at the values
   ├─ components_boardN.py   a sized part: `proposed`, the study named in the note
   ├─ design/STATUS.md       a Decided row if it commits the design; an Open item if it opens one
   ├─ the handoff            a layout rule it implies (s03 → thermal copper)
   └─ history/HISTORY.md     ALWAYS — what was asked, found, and ruled out; failures too
```

A study **prints**; it never writes SPECS, a value bus or the handoff itself.
Moving those homes is a reviewed step (the `decision` skill), and that review
is where a wrong result gets caught.

## Anatomy of a study

`_template.py` is the skeleton. Each example follows it:

```python
"""
Study 2 -- <the question in a few words>.

Question  <answerable with a number or a yes/no>
Decides   <what the answer sets: a SPECS row, a value-bus line, a decision, a layout rule>
Inputs    designpoint: <the PARAMS keys it reads>
Headline  <tag>.<metric>_<unit>, ...                    -> SPECS section <n>
"""
import designpoint as DP

def analyse():            # the computation; returns plain numbers
    k = DP.kw()           # every input from the design point, never a local constant
    ...

def headline():           # the numbers SPECS quotes -> guarded by --check
    return {"divider.worst_tol1_pct": ...}

def main():               # human-readable result, ending in one "-> conclusion" line
    ...
```

`main()` and `headline()` both call `analyse()`, so the number you read and
the number `--check` guards cannot drift apart.

## Where each number lives

| kind of number | its one home | example |
|---|---|---|
| requirement, limit, published result | `design/SPECS.md` | 3V3 accuracy ±3 % (H), source `s02` |
| model input: operating condition, datasheet constant, design choice not yet a part | `studies/designpoint.py` | `vref_tol` 1 %, "datasheet p.7" |
| a physical part on a board | `studies/components_boardN.py` (the value bus) | R1 35.7 k 0.5 %, note `s02` |
| a guarded headline value | `studies/baselines/headline.json` (generated by `--bless`) | `divider.worst_tol1_pct` |
| plots, dumps | `out/` (disposable, gitignored) | `out/s02_divider_tolerance.png` |
| a write-up worth keeping (a part survey, a trade study) | `studies/reports/<date>_<name>.md` | `2026-11-02_ldo_survey.md` |
| the story, failures included | `history/HISTORY.md` | `### Study 2 — …` |

**A value lives in `designpoint.py` until it becomes a part on a board; then
it lives in that board's value bus, and the design-point row is deleted.**
From then on a study reads it back from the bus, so it checks the design as
drawn rather than a copy that can go stale. The bus row carries the numbers
in an optional sixth field, which the handoff ignores:

```python
# studies/components_board1.py
("R1", "3V3 divider, top", "<MPN> -- 35.7 k 0.5 % 0402", "set",
 "s02_divider_tolerance: worst case 2.24 % against +-3 % (H)",
 {"value": 35.7e3, "tol": 0.005}),

# in a study
from common import part
r1 = part("board1", "R1")          # {"value": 35700.0, "tol": 0.005}; raises if absent
```

A design-point row that restates a SPECS value (an input range, an ambient)
cites the SPECS section. Change both in the same pass.

## Running

    .venv/bin/python studies/run_all.py --list                 # what each study answers
    .venv/bin/python studies/run_all.py --only s02             # one (its number is enough)
    .venv/bin/python studies/run_all.py                        # all of them, in order
    .venv/bin/python studies/run_all.py --check                # headlines vs the baseline
    .venv/bin/python studies/run_all.py --check --bless        # accept them: a claim you looked
    HW_JOBS=1 .venv/bin/python studies/run_all.py --check      # force serial

`--check` reports every headline that moved, appeared (NEW) or disappeared
(GONE). Either the model moved and SPECS must follow, or something broke.
Decide which **before** blessing.

## Rules, each with its reason

- **Inputs come only from `designpoint.kw()`.** It raises on an unknown name,
  so a typo or a forgotten parameter cannot quietly fall back to a default. A
  default that silently decides a headline is the failure this design exists
  to prevent.
- **Deterministic or it is not guarded.** Fix every seed (`mc_seed`, one
  generator per job). `par.pmap` returns results in job order, so a parallel
  sweep is byte-identical to the serial one, and `--check` can use tight
  tolerances.
- **Headline keys are `<tag>.<metric>_<unit>`.** The unit is for the reader.
  `--check` allows each number a millionth of its own value — relative, so a
  60 µA figure is guarded as tightly as a 5 V one; a number that legitimately
  wobbles more gets a line in `baseline.REL` with the reason. A headline may
  also be text (a chosen package) or `None`; those are compared for equality.
- **SPECS cites the key.** A row sourced from a study names it and the key in
  backticks — `` `s02_divider_tolerance` — `divider.worst_tol0p5_pct` `` — and
  the doc lint fails a cited key the baseline does not hold.
- **Quote the achieved value, never the target** (`s01`: the target is
  1600 Hz; the E96 resistor gives 1592 Hz, and that is what SPECS says).
- **Against a hard line, the worst case decides**; statistics say how often.
  Meet a hard line with margin, not on paper (`s02`: 1 % parts pass by 0.03 %,
  because the E96 grid spent 0.5 % before any tolerance).
- **A budget is evaluated at the corner**: maximum input, maximum load,
  maximum ambient, all at once. Every constant cites its datasheet page (`s03`).
- **A negative result is a result.** "No class passes", "the simpler topology
  is 4 dB short": write it in HISTORY as carefully as a success. It is the
  entry that stops the next person re-running it.
- **Numbers are never edited by hand.** Re-run, look, bless.
- **Numbering:** the next free `sNN`, never reused. A superseded study moves
  to `history/archive/` (with a HISTORY line saying why), and its baseline keys
  leave through a `--bless`.
- **Measurement conventions** (units, windows, test levels, what is always
  reported beside a headline) are the project's, in `CLAUDE.md`. Every study
  follows them, and so does the bench.

## The examples — read them, then delete them

| file | pattern | what it teaches |
|---|---|---|
| `s01_rc_corner.py` | derivation | ideal → standard value → the achieved number is what gets published |
| `s02_divider_tolerance.py` | robustness | worst case + seeded Monte Carlo in parallel; E-series snapping cost; the margin rule; a plot in `out/` |
| `s03_ldo_thermal.py` | budget + trade | the corner, cited constants, headroom not just pass/fail; a result that becomes a handoff layout rule |

They share the `EXAMPLE` rows in `designpoint.py`, the example rows in
`design/SPECS.md`, the example entries in `history/HISTORY.md` and the blessed
numbers in `baselines/headline.json`. They go together — a SPECS row citing a
study that is gone fails the doc lint — so remove them in one step:

    ./setup.sh clean-examples [--dry-run]

then `./verify.sh`, and bless your own first headline with `--check --bless`.
